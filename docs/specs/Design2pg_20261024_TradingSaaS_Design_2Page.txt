
AI Agentic Saas Researcher for Trading
Software design specification summary
Version 2 • 24 October 2026 • Page 1 of 2
1 How the product will be built
The design implements Requirements R001–R074. It selects components, class responsibilities, storage, algorithms and REST/SSE contracts; it is not another list of business wishes. Customer payments remain simulated. Actual provider costs and latency are measured. Implementation and validation are still required before production readiness can be claimed.
Use a modular monolith with Next.js and TypeScript, FastAPI API processes, separate Python workers and a private authenticated MCP service. PostgreSQL is authoritative for accounts, execution, events and accounting. Redis supports cache, quotas and notifications; losing Redis cannot lose accepted jobs. Use encrypted object storage, LangSmith and infrastructure telemetry.
2 OOAD and durable workflow
Domain objects include Account, Session, ResearchRun, EvidenceBundle, Wallet and UsageRecord. Application services coordinate use cases; repositories isolate database access; injected adapters isolate market, news, models and dummy payments. Reuse pure Python functions for indicators, conversions, validation, pricing and statistics. Agents cannot execute arbitrary SQL or mutate wallets.
Research admission atomically checks operation-key deduplication, demo credit and real spending allowance, then creates reservations, run, job intent and events. Workers claim short leases with fencing generations. They release database locks before provider calls. Durable polling and an outbox make lost notifications recoverable.
LangGraph persists run-scoped state and checkpoints; LangChain supplies model/tool abstractions. Price, News and Technical branches produce typed evidence independently, then join for validation and Signal synthesis. Persist call intent, provider result and usage before advancing. Recovery reuses completed outputs and reconciles ambiguous chargeable calls; it cannot promise exactly-once execution by an external provider.
3 Trust and session boundaries
FastAPI derives account context from secure server-backed cookies. Use CSRF protection, session rotation, optional verified Google OIDC, hashed tokens and administrator MFA. PostgreSQL row policies reinforce service authorization. Graph threads, artifacts, exports and streams are account-scoped.
MCP exposes allowlisted read-only tools. Validate arguments, results, units, timestamps, provenance and instrument identity. Keep untrusted excerpts separate from instructions. Sanitize rendered output, constrain network destinations and exclude secrets and hidden model reasoning from prompts, traces and public activity.

4 Data and actual cost accounting

PostgreSQL stores identity/sessions, instruments and mappings, conversations, runs/nodes, jobs/leases/outbox, checkpoints, evidence/reports/citations, calls/usage, validations, audit events, demo wallets/journals, evaluations and rollups. UUIDs, ownership-aware foreign keys, exact NUMERIC costs and UTC timestamps support integrity. Large encrypted artifacts use database references; secrets belong in a secret manager.
DummyPaymentProvider generates controlled success, failure, pending, expiry and refund events. Unique event IDs and balanced immutable demo journals prevent repeated credits. Payment responses declare simulation and zero collection; public payment webhooks are disabled. Real expense records and real spend reservations are separate. Token-rate calculations remain labelled calculated until provider reconciliation. Unknown usage never becomes fabricated actual usage.
5 Browser APIs and streaming
One HTTPS origin routes /api/v1 to FastAPI. POST /research/estimates snapshots the request; POST /research/runs returns 202 and a durable run ID. GET run snapshots, reports, usage and activity provide authoritative data. Explicit cancellation uses a guarded state change. The full design contains authentication, catalogue, billing, reports, admin and export route registries.
GET /research/runs/{id}/events streams one run; GET /events streams account changes. Persist scope-specific ordered event IDs, replay with Last-Event-ID, deduplicate and refresh snapshots after terminal events. Heartbeat every 15 seconds. Bound slow-client buffers and recheck sessions. A stream controller recovers from expired cursors and authentication failures without endless reconnects.
The frontend composes ResearchForm, RunStatus, ActivityPanel, EvidencePanel, ReportPanel and UsagePanel around a typed API client. Snapshots remain authoritative. Publish complete OpenAPI 3.1 and event JSON Schemas before independent consumer implementation; the DOCX is not executable schema.
6 Recovery deployment and verification
Cancellation and completion race through conditional state updates; fencing blocks stale workers. Enforce deadlines, bounded retries, fair queueing, circuit breakers and approved fallbacks. Cache only under matching identity, entitlement and freshness. LangSmith traces supplement durable records; exporter outages queue diagnostics and raise alerts.
Deploy containerized API and workers separately, managed PostgreSQL, private data services, encrypted backups, migration/rollback discipline and monitored spend. Test load, cancellation, duplicate events, isolation, checkpoint recovery, deletion restoration and provider contracts. Collect release evidence against the requirements map; target SLOs are not demonstrated achievements.
The full Software Design Specification version 2 is authoritative for implementation detail. It preserves the detailed version 1 REST/SSE baseline with simulation semantics and adds explicit transaction, recovery and ownership decisions. Live commerce requires a separate approved change.
